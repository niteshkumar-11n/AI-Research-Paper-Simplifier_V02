OVERVIEW
──────────────────────────────────────────────────
• The study examines software project failure rates through a global Web survey conducted in 2005 and 2007.
• It challenges the prevailing view that there is a software crisis by presenting evidence that suggests the overall project failure rate is high but not as alarming as previously thought.
• The research aims to estimate actual cancellation rates, identify factors impacting cancellations, assess project success rates for completed projects, and explore whether project size affects these outcomes.

──────────────────────────────────────────────────
METHODOLOGY
──────────────────────────────────────────────────
• A replicated international Web survey was conducted targeting IT departments (developing management information systems) in 2005 and 2007.
• Cancellation was measured using a binary question, defining it as a project that did not deliver any usable functionality by the first release.
• Project size was measured based on duration to first release and peak staffing. Performance of completed projects was assessed using five success criteria.

──────────────────────────────────────────────────
KEY POINTS
──────────────────────────────────────────────────
• The cancellation rate decreased from 15.52% in 2005 to 11.54% in 2007, but this decrease is not statistically significant.
• Requirements and scope changes, along with lack of senior management involvement, were the most common reasons for project cancellations.
• Most respondents felt that user satisfaction, product quality, and staff productivity were either good or excellent.
